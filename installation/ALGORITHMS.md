# Кейсы: Spark SQL + GraphFrames

Биллинг и события на БС читаются коннектором из ClickHouse. Считать граф внутри CH нельзя: один раз выгрузить рёбра/вершины, `.cache()` / `persist(MEMORY_AND_DISK)`, дальше только Spark.

На одного абонента не гонять PageRank/CC по всей сети — вырезать эго-граф (1–2 хопа) или след по его БС.

---

## Когда что

| Слой | Инструмент | Зачем |
| --- | --- | --- |
| Время, вышка, окна, baseline | Spark SQL | pattern of life, телепорт, co-travel, всплески |
| Рёбра и итерации | GraphFrames | цепочки, сообщества, PageRank, треугольники, пути |
| Запись результата | CH / S3 | не `collect` на driver |

Типичная джоба: SQL из CH → маленький GraphFrame вокруг семени (или суточный граф сети) → результат обратно.

---

## Какие графы строить

**Звонки.** `A → B`, вес = число вызовов / минуты. Ориентированный. Основной социальный граф.

**Абонент — БС.** `user → tower`, вес = сколько раз бился / длительность. Двудольный. География и колокация.

**БС — БС.** Ребро, если один IMSI за окно побывал на двух вышках. Вес = число таких абонентов. Коридоры и опорные соты.

Начать со звонков + «абонент—БС». Граф миграции БС — когда первые два уже кэшируются.

Рёбра — только id + нужные поля. Строки и JSON на ребре раздувают RAM.

## Кейсы на всю сеть

### Степени и изоляты

Степень вершины, входящие/исходящие, `dropIsolatedVertices`.

Кто только принимает, кто только звонит, номера без трафика, вышки без абонентов. Первый проход по любому графу.

*Пример:* ночь, массовый инцидент на сети — по исходящей степени сразу видны площадки автообзвона vs мёртвые sim, которые только принимают сервисные SMS.

### PageRank (хабы сети)

Важные вершины по структуре, не по объёму минут.

На звонках — транзитные номера, серые АТС, «телефонные площадки». На графе БС — соты, через которые течёт движение.

*Пример:* не самый «толстый» по минутам номер оказывается хабом, потому что через него завязаны десятки мелких групп. У оператора так находят серый транзит; в метаданных разведки — узлы, вокруг которых имеет смысл строить цепочку.

### Звезда vs клика (`triangleCount`)

Плотные тройки A–B–C против «один ко многим без связей между листьями».

Колл-центр, SIM-box, автоинформатор: огромная степень, треугольников почти нет. Семья / двор / смена: меньше степень, много треугольников.

*Пример:* SIM-box на офисной АТС бьёт тысячи B-номеров и не образует клик. Трое соседей по подъезду, которые ещё и звонят друг другу, дают треугольники. Тот же тест используют и антифрод, и разбор инфраструктуры vs живых людей.

### Connected Components

Связные куски графа.

На полном суточном биллинге обычно одна гигантская компонента и хвост мелочи. Смотреть хвост: закрытые группы, ведомственные сети, «островок» региона после аварии линка.

*Пример:* корпоративный VPN голоса / закрытая АТС видна как компонента, слабо связанная с остальной сетью. После разреза магистрали между городами компоненты распадаются по географии.

### Label Propagation

Сообщества без заданного числа кластеров. Дёшево как разведка, шумно как истина.

На звонках — круги общения. На «абонент—БС» уезжает в географию (кластер ≈ район покрытия).

*Пример:* неделя звонков в небольшом городе склеивает «школа / двор / работа» грубыми пятнами. Для точного COI одного человека лучше эго-граф, не LPA на всей сети.

### K-Core

Снять шелуху разовых наборов, оставить ядро постоянных связей.

*Пример:* у оператора «ядро» — кто реально держит сеть (постоянные взаимные), периферия — разовые входящие с рекламных и сервисных номеров. В антифроде периферию отбрасывают, чтобы не кормить модель мусором.

### Граф миграции БС

Агрегат «кто перешёл с соты A на соту B» за окно.

Коридоры (трасса, метро), опорные соты, аномальные рёбра (нет радиососеда, но много миграций — сбой тайма или массовый роуминг).

*Пример:* утро — толстое ребро жилой район → деловой центр. Ребро «посёлок ↔ другой конец страны» за 10 минут — не коридор, а ошибка/клон IMSI (см. телепорт ниже).

## Кейсы на одного абонента U

Данные резать окном (сутки/неделя). 2-хоп только с обрезкой: взаимные, ≥N минут, не короткие, не АТС. Массовые БС (вокзал, стадион) — порог: несколько общих сот с U или те же ночные.

### 1 хоп (прямые контакты)

Кто звонил U / кому звонил U: счётчик, минуты, входящие vs исходящие, взаимность.

*Пример:* 4 номера, много минут, почти всё взаимно — быт. 800 уникальных B за день, обратных нет — обзвон или серый исходящий.

### Community of interest

Не все, до кого дозвон, а кто важен: взаимность, частота, нетипичное время.

Считается на эго-графе: веса, triangles, Personalized PageRank от U. Обычно 5–30 номеров, не тысячи.

*Пример:* у менеджера в COI — семья, два коллеги и один «рабочий» номер склада, хотя в CDR ещё 200 разовых клиентов. В цепочках метаданных COI — рабочий круг селектора, не полный 1-хоп.

### 2 хопа / contact chaining

BFS или `shortestPaths` с landmark = U. Друзья друзей после обрезки.

*Пример:* публичный приём АНБ — разворачивать селектор на 1–2 хопа по метаданным. На биллинге то же: 2 хопа без фильтра раздуваются до сотен тысяч (сервисные, колл-центры). С фильтром остаётся обозримый круг.

### Personalized PageRank от U

Кто близок по структуре, даже если прямых минут мало.

*Пример:* номер, который редко звонит U, но сидит в том же плотном круге коллег. Кандидат в COI и кандидат «на кого ещё посмотреть» при разборе инцидента / фрода.

### Треугольники в эго-сети

Сколько троек U–A–B, где A и B тоже связаны.

Высоко — социальный круг. Ноль при большой степени — площадка.

*Пример:* та же эго-сеть, что «семья» vs «автоинформатор», но уже не на всей сети, а вокруг одного MSISDN — считается за секунды.

### Motifs вокруг U

Только на подграфе, не на миллиарде рёбер.

- `U → X → U` — перезвоны
- `U → X → Y → U` — маленькие кольца
- много `U → X` без обратных и без рёбер между X — звезда
- `user → tower ← user` — двое на одной БС (колокация, если есть окно времени)

*Пример:* взаимные перезвоны вечером — быт. Звезда коротких исходящих ночью — обзвон. Два IMSI на одной БС без CDR между ними — встреча в эфире, не звонок.

### Путь до известного семени

BFS / `shortestPaths` от U до номера из чёрного списка (или наоборот).

*Пример:* антифрод — новый абонент в 1–2 хопах от уже отключённого SIM-box. Разбор инцидента — насколько близко VIP к скомпрометированному номеру.

### Broker / cut-out

В эго+2 хопа: мало треугольников, стоит между двумя плотными кусками.

*Пример:* «телефон для связи» между двумя бригадами, диспетчер, серая площадка. В метаданных — классический посредник: сам не клика, но без него два сообщества распадаются.

### Иерархия по направлению

Ориентированный BFS на узком COI: кто преимущественно звонит «вниз», кто только принимает «сверху».

*Пример:* внутренняя оргструктура по корпоративной АТС (руководитель → секретарь → линейные). На всём биллинге города это не работает — только на уже выделенном COI.

### Циклы на подграфе

`detectingCycles` / motif кольца A→B→C→A вокруг U или его COI.

*Пример:* взаимный прогон минут между несколькими sim (накрутка, взаимозачёт). Короткое кольцо в COI — иногда просто «перезвонили через третьего».

### Профиль БС (pattern of life)

Топ сот U × час × день недели. Дом / работа / трасса — обычно 2–5 доминирующих БС.

*Пример:* будни 09–18 одна сота у бизнес-центра, ночь — жилой сектор. Смена ночной соты на другой регион без командировки в биллинге — аномалия (см. телепорт, смена SIM).

### Соседи по эфиру (колокация)

Другие IMSI на тех же БС в тех же слотах. Сначала топ-вышки U, не все вышки сети.

*Пример:* кто ездит тем же составом смены или живёт на тех же ночных сотах, даже если в CDR друг друга нет. Публичный аналог — co-travelers по локационным метаданным.

### Прыжки по БС (телепорт)

Последовательность сот во времени. Норма — радиососеди. Аномалия — сотни километров за минуты.

*Пример:* клон IMSI / ошибка в CDR / резкий roaming-глюк. У оператора — фрод и качество данных. По следу «человек не мог там оказаться» — тот же сигнал.

### Смена селектора (новая SIM, старый след)

Новый MSISDN/IMSI, но тот же набор сот в те же часы и/или тот же 1-хоп COI (Jaccard по соседям и по БС).

*Пример:* абонент перевыпустил SIM и «переехал» на новый номер — COI и ночные БС почти те же. В антифроде — «сгоревший» номер, который всплыл соседним IMSI с тем же кругом. В метаданных — смена селектора без смены человека.

### Всплеск после события

Сравнение окна с baseline той же недели: новые B, ночные, короткие, новая география.

*Пример:* после аварии на БС — шквал звонков в техподдержку (звезда на один B). После отключения площадки — её COI начинает набирать запасные номера (новые рёбра у того же круга).

### Convening без звонка

Два следа пересеклись на одной (или соседних) БС, CDR между ними нет. Разово, без требования «ездили неделю вместе».

*Пример:* два человека на одной соте у ТЦ в одно окно, в звонках друг друга нет. Это не доказательство встречи, но сигнал колокации; дальше только если есть право и другие признаки.

## Co-travelers

Join следов по `(bs, time_bin)`, затем порог: несколько **разных** БС / несколько дней, не одна сота вокзала.

Строится SQL. Если нужна графовая близость — спроецировать в ребро `user–user` («вместе N слотов») и уже PPR/компоненты.

*Пример:* два IMSI будничным утром на жилой соте, днём на одной офисной, вечером снова жилая — совместный маршрут, хотя за неделю ни одного звонка друг другу. Разовый стадион на 40 тысяч IMSI — не co-travel, отсекается порогом по числу различных сот.

## Агрегаты на эго-сети

`aggregateNeighbors` / `aggregateMessages` / Pregel — когда стандартного алгоритма мало: прогнать по соседям «число уникальных БС у круга U», «доля взаимных», «макс. степень соседа».

*Пример:* у U пять контактов, у каждого из них по 2 тысячи исходящих без треугольников — U сидит рядом с площадками, даже если сам звонит «как обычный».

## Порядок на практике

1. Сутки–неделя звонков: степени, звёзды, PageRank хабов.
2. Эго-граф выбранного U: 1 хоп, COI, triangles, PPR.
3. След U по БС: pattern of life, телепорт.
4. Колокация / co-travel по топ-сотам U (SQL).
5. 2 хопа с обрезкой, путь до известных семян.
6. Сравнение с прошлым окном: новые контакты, новые БС, похожий след на другом IMSI.
7. По желанию — суточный граф БС→БС (коридоры).

Motifs, cycles, LPA — на подграфе или как второй заход, не на сыром месяце всей сети.

## Память (ориентир, одна тачка ~56 CPU / ~400 ГБ heap)

После чтения из CH данные живут в Spark. ClickHouse на другом сервере.

| Задача | Комфортно | С spill |
| --- | --- | --- |
| Степени, фильтры, агрегаты | 2–5 млрд рёбер | до ~10 млрд |
| PageRank, LPA, BFS | 0.3–1 млрд | 1–3 млрд |
| Connected Components | 100–500 млн | ~1 млрд + checkpoint на NVMe |
| Triangle count | десятки–сотни млн | ~0.5 млрд; режет power-law |
| Motifs | эго-граф / сэмпл | не весь биллинг |
| Один U (1–2 хопа) | тысячи–сотни тысяч рёбер | массовые БС резать порогом |

Executors: несколько JVM (например 7×8 cores × ~56g), не одна на 56 ядер и 480g. Shuffle — локальный NVMe. Driver 8–16g, граф на него не собирать.
