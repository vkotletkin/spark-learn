# Кейсы: GSM / GPRS

Две таблицы в ClickHouse, в Spark — коннектором.

1. **Соединения** — факты установки: GSM (голос/SMS) и GPRS (PDP/сессия). Кто, когда, тип, длительность/байты, для GSM
   часто A и B, для GPRS — APN.
2. **Положение** — где был абонент: IMSI, время, CGI/LAC (и координаты соты, если есть).

Граф — из соединений. Место и co-travel — из положения. Связка: join по IMSI и времени (положение на момент соединения
или ближайшее).

Окно резать в CH, в Spark `.cache()`. На одного IMSI не гонять алгоритмы по всей сети.

---

## Как стыковать таблицы

На момент соединения взять положение того же IMSI (as-of: последнее положение ≤ ts, с разумным TTL, иначе дырка).

Получается факт: *кто с кем/куда соединился и откуда по карте*. Без положения граф слепой. Без соединений положение —
только эфир, без «зачем был на соте».

GSM и GPRS не смешивать в одном ребре без поля `type`: голос A→B и PDP на APN — разные графы, один IMSI.

## Графы из соединений

**GSM: A → B.** Вес = число установок / длительность. Ориентированный. Основной социальный граф.

**GPRS: IMSI → APN** (или GGSN). Вес = сессии / байты. Сервисы, не люди. Ребро IMSI–IMSI из GPRS нет, пока не
спроецируете «оба в одном APN в одном окне» — это слабый признак.

**IMSI → CGI в момент соединения.** Джойн с положением. «Откуда звонил / откуда поднял PDP».

Рёбра — id + счётчики, не сырой поток каждой установки за месяц.

---

## Положение

След: последовательность CGI/LAC во времени. Если есть lat/lon соты — точки для Sedona.

**Pattern of life.** Топ CGI × час × день. Ночь / будни / GPRS днём vs редкий GSM ночью.

**Телепорт.** Смена CGI быстрее, чем позволяет расстояние между центроидами.

**Co-travel.** Self-join положения по `(CGI, time_bin)` (или соседние соты + слот). Порог: несколько **разных** CGI /
дней, не одна вокзальная сота.

Один IMSI / пачка семян — **ClickHouse**. Все со всеми — CH отсекает жирные бины, Spark если нужен граф IMSI–IMSI.

**Смена SIM.** Новый IMSI, тот же ночной набор CGI (Jaccard). Если в соединениях тот же круг A/B — сильнее, чем одно
положение.

## Кейсы на соединения (GSM)

Степени, взаимность, `dropIsolatedVertices` — площадка vs быт.

**PageRank** — хабы (серые АТС, транзиты), не «кто больше минут».

**Triangle count** — клика (круг людей) vs звезда (обзвон, SIM-box): большая степень, треугольников нет.

**Connected Components** — острожки; на полном дне обычно гигант + хвост. Смотреть хвост.

**Personalized PageRank / BFS / shortestPaths** — COI и цепочка от одного U, путь до известного семени. 2 хопа только с
обрезкой (взаимные, не короткие).

**Motifs** только на эго-графе: `U→X→U`, звезда, кольцо.

**K-core / Label Propagation** — ядро постоянных связей, грубые сообщества.

*Пример:* GSM-установки ночью на тысячи уникальных B без взаимности — обзвон. Трое, у кого взаимные установки и общие
ночные CGI из положения — быт, не площадка.

---

## Кейсы на соединения (GPRS)

Топ APN у IMSI, аномальный APN, объём vs обычный профиль.

Граф IMSI–APN: кто сидит на одном сервисе. PageRank APN — популярные шлюзы. Звезда IMSI→много APN за час — сканер/модем,
не телефон.

Джойн с положением: PDP с «домашней» CGI vs PDP с соты, где этот IMSI никогда не ночевал.

*Пример:* днём GPRS с офисной CGI, ночью почти нет сессий — норма. Всплеск PDP с чужого LAC и нового APN — другая sim
или прокси.

---

## Кейсы на положении

**Колокация / co-travel / convening** — оба в эфире в слоте, соединения между ними может не быть.

**PrefixSpan / FP-Growth** — частые цепочки и наборы CGI (маршрут, «корзина» сот). Два IMSI с тем же itemset ночных
CGI — кандидат смены селектора.

**DBSCAN** (Sedona) — сгустки точек следа: дом/работа; дорога — шум. На вход агрегаты (CGI×слот или точки одного U), не
каждый пинг всей сети. В CH это не DBSCAN, а `group by` geohash/CGI.

**Gi\*** (Sedona) — какие соты горячее **соседей** по числу уникальных IMSI или числу соединений (джойн таблиц → \(x\)
на CGI). Агрегат в CH, Gi\* на центроидах сот. Топ Erlang-подобных счётчиков в CH — не Gi\*.

**KNN / buffer** — кто из положений попал в радиус/полигон.

*Пример:* два IMSI без GSM-ребра, но будни один и тот же набор CGI — co-travel. Gi\* по uniq IMSI в положениях подсветит
стадион vs тихую окраину, где внезапно много установок GPRS.

## Вместе (соединение × положение)

Имеет смысл именно эта связка.

| Вопрос                             | Как                                               |
|------------------------------------|---------------------------------------------------|
| Откуда U ставил GSM/GPRS           | join, профиль CGI соединений vs весь след         |
| Звонил с места, где его обычно нет | соединение на CGI вне top-N жизни                 |
| COI + кто рядом в эфире            | граф GSM ∪ колокация из положения                 |
| Площадка                           | звезда в GSM + много IMSI с одной CGI в положении |
| Новая SIM                          | Jaccard положения + пересечение B-номеров / APN   |
| Всплеск                            | пик установок и пик uniq IMSI на тех же CGI       |
| Телепорт во время сессии           | положение до/после установки, дырка TTL           |

*Пример:* GSM A→B как раньше, но все установки B за день с одной CGI и кучи IMSI в положении на ней — не «круг общения»,
а точка в пространстве (офис, БС у рынка). GPRS в APN internet с той же CGI ночью — тот же человек в том же месте,
другой тип соединения.

---

## Один абонент U

1. CH: его соединения (GSM отдельно, GPRS отдельно) + его положение за окно.
2. Join: каждое соединение с CGI.
3. Pattern of life и телепорт по положению.
4. Эго-граф GSM (1 хоп, взаимные), APN-профиль GPRS.
5. Co-travel по его топ-CGI (не по вокзалу без порога).
6. DBSCAN его точек; при необходимости PPR/triangles на маленьком графе.
7. Сравнение с прошлым окном: новые B, новые APN, новые ночные CGI.

## Порядок на практике

1. Сутки соединений GSM: степени, звёзды, хабы.
2. GPRS: APN, объёмы, странные сессии.
3. Положение U: life, телепорт, co-travel.
4. Join: откуда ставились соединения.
5. Эго-граф U + колокация.
6. По координатам — DBSCAN следа / Gi\* по сотам.
7. Новые IMSI с тем же положением и тем же кругом B/APN.

## Память (ориентир, ~56 CPU / ~400 ГБ heap)

В граф — агрегаты соединений, не каждая установка. Положение плотнее соединений: в Sedona/граф — сжатый след.

| Задача                               | Комфортно                          |
|--------------------------------------|------------------------------------|
| Один U, обе таблицы                  | CH + маленький GraphFrame          |
| PageRank / BFS на GSM-рёбрах         | 0.3–1 млрд рёбер после агрегата    |
| Triangle count                       | десятки–сотни млн; режет power-law |
| Motifs                               | только эго-граф                    |
| DBSCAN одного U                      | тысячи–сотни тысяч точек           |
| Gi\* по сотам                        | тысячи CGI                         |
| Co-travel всех на вокзале без порога | не считать                         |

Executors: несколько JVM (например 7×8 cores × ~56g). Shuffle — NVMe. Driver 8–16g.
