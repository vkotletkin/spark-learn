# S3 / object storage

Документация Spark: [Integration with Cloud Infrastructures](https://spark.apache.org/docs/latest/cloud-integration.html).

Модуль `spark-hadoop-cloud` даёт коннекторы к object storage. Это не отдельный сервис Spark: нужны JAR-ы на classpath и credentials. После этого данные читаются и пишутся по URL.

| Стор | URL |
| --- | --- |
| Amazon S3 / MinIO | `s3a://bucket/path` |
| Azure ADLS Gen2 | `abfs://container@account.dfs.core.windows.net/path` |
| GCS | `gs://bucket/path` |

Рабочий коннектор для S3 — **s3a**. Схемы `s3://` и `s3n://` лучше не использовать.

Дистрибутив `spark-4.2.0-bin-hadoop3` эти библиотеки **не содержит**.

Object store — не замена локальным дискам. Shuffle, spill и checkpoint остаются на NVMe (`SPARK_LOCAL_DIRS` в [CONF.md](CONF.md)). S3 — для исходных данных и результатов.

---

## Зависимость Maven

В `pom.xml` уже добавлено:

```xml
<dependency>
  <groupId>org.apache.spark</groupId>
  <artifactId>spark-hadoop-cloud_2.13</artifactId>
  <version>${spark.version}</version>
  <scope>${spark.scope}</scope>
</dependency>
```

`provided` (сборка кластерного uber-jar): облачные JAR-ы **не** попадают в `spark-learn-1.0.0-uber.jar`. Их нужно дать Spark отдельно.

`-Plocal` (IDE без `spark-submit`): зависимость становится `compile`, JAR-ы подхватываются локально.

Не переводите scope в `compile` для shade: AWS SDK bundle очень большой и легко конфликтует с Hadoop на кластере.

### `spark-submit --packages`

Удобно для проверки:

```bash
bin/spark-submit \
  --master spark://localhost:7077 \
  --packages org.apache.spark:spark-hadoop-cloud_2.13:4.2.0 \
  --class com.sparklearn.Main \
  /Users/vladislavkotletkin/development/spark-learn/spark-learn/target/spark-learn-1.0.0-uber.jar
```

### `$SPARK_HOME/jars`

Для постоянного кластера положить JAR-ы модуля и транзитивных зависимостей в `$SPARK_HOME/jars` **на всех узлах** (Master и Workers). Тогда `--packages` не нужен.

## Аутентификация

Секреты не коммитить в git и не класть в исходники.

`spark-submit` читает переменные окружения и прокидывает их в s3a:

```bash
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
# при необходимости:
export AWS_SESSION_TOKEN=...
export AWS_ENDPOINT_URL=...
```

Либо в `conf/spark-defaults.conf` (только локально, не в репозиторий):

```properties
spark.hadoop.fs.s3a.access.key  YOUR_KEY
spark.hadoop.fs.s3a.secret.key  YOUR_SECRET
```

На EC2/EKS обычно хватает instance / IRSA credentials, ключи не нужны.

### SeaweedFS (локально)

Compose: [seaweedfs/docker-compose.yml](seaweedfs/docker-compose.yml).

```bash
docker compose -f installation/seaweedfs/docker-compose.yml up -d
```

| Что | Адрес |
| --- | --- |
| S3 API | `http://localhost:8333` |
| Master UI | `http://localhost:9333` |
| Filer UI | `http://localhost:8888` |
| Bucket | `spark` |
| access key | `spark` |
| secret key | `sparksecret` |

Ключи только для локальной разработки, не для production.

`spark-defaults.conf` (Spark на хосте):

```properties
spark.hadoop.fs.s3a.endpoint                      http://localhost:8333
spark.hadoop.fs.s3a.path.style.access             true
spark.hadoop.fs.s3a.connection.ssl.enabled        false
spark.hadoop.fs.s3a.aws.credentials.provider      org.apache.hadoop.fs.s3a.SimpleAWSCredentialsProvider
spark.hadoop.fs.s3a.access.key                    spark
spark.hadoop.fs.s3a.secret.key                    sparksecret
```

Пути в коде: `s3a://spark/input/`, `s3a://spark/output/`.

Создать bucket вручную, если `init-bucket` не успел:

```bash
echo "s3.bucket.create -name spark" | docker compose -f installation/seaweedfs/docker-compose.yml exec -T master weed shell -master=master:9333
```

Или через AWS CLI:

```bash
aws --endpoint-url http://localhost:8333 s3 mb s3://spark
```

Остановка:

```bash
docker compose -f installation/seaweedfs/docker-compose.yml down
```

Данные живут в Docker volumes. Полная очистка: `docker compose ... down -v`.

### Другой S3-compatible (MinIO и т.п.)

## `spark-defaults.conf`

Запись в S3 через обычный `FileOutputCommitter` идёт через `rename()`. На S3 это медленно и ненадёжно. Нужен S3A committer (zero-rename):

```properties
spark.hadoop.fs.s3a.committer.name                directory
spark.sql.sources.commitProtocolClass             org.apache.spark.internal.io.cloud.PathOutputCommitProtocol
spark.sql.parquet.output.committer.class          org.apache.spark.internal.io.cloud.BindingParquetOutputCommitter

spark.hadoop.parquet.enable.summary-metadata      false
spark.sql.parquet.mergeSchema                     false
spark.sql.parquet.filterPushdown                  true
```

`INSERT OVERWRITE` / `mode("overwrite")` с динамическими партициями **не работает** с S3A committers:

```text
PathOutputCommitter does not support dynamicPartitionOverwrite
```

Дополнительно для AWS: ограничить жизнь незавершённых multipart-загрузок, иначе они копят деньги. Каталоги `_temporary` периодически чистить.

## Примеры кода

```scala
import org.apache.spark.sql.SparkSession

val spark = SparkSession.builder()
  .appName("spark-learn-s3")
  .getOrCreate()

val inputPath = "s3a://bucket/input/"
val outputPath = "s3a://bucket/output/"

val df = spark.read.parquet(inputPath)

df.write
  .mode("overwrite")
  .parquet(outputPath)
```

Текст:

```scala
val lines = spark.sparkContext.textFile("s3a://landsat-pds/scene_list.gz")
lines.take(5).foreach(println)
```

CSV:

```scala
val csv = spark.read
  .option("header", "true")
  .csv("s3a://bucket/data.csv")

csv.write
  .mode("overwrite")
  .option("header", "true")
  .csv("s3a://bucket/out-csv/")
```

Credentials в коде (только если нельзя использовать env / `spark-defaults.conf`):

```scala
val spark = SparkSession.builder()
  .appName("spark-learn-s3")
  .config("spark.hadoop.fs.s3a.access.key", sys.env("AWS_ACCESS_KEY_ID"))
  .config("spark.hadoop.fs.s3a.secret.key", sys.env("AWS_SECRET_ACCESS_KEY"))
  .getOrCreate()
```

Не хардкодить ключи в исходниках.
